## [1.1.1](https://github.com/mnafshin/springdocker/compare/v1.1.0...v1.1.1) (2026-07-12)

### Fixed

- Dockerfile generation detects which Gradle descriptor files exist and emits the correct `COPY` line for `.gradle` vs `.gradle.kts` projects (closes #130).
- After `springdocker init`, the next-step hint now reads `next: springdocker dockerfile generate` (closes #131).
- `SECURITY.md` supported versions updated for the 1.x line (closes #133).
- Generated Gradle Dockerfiles now select the boot JAR (excluding `*-plain.jar`) and copy it to a stable `build/libs/application.jar` path after `bootJar` (closes #135).
- Default digest pinning for generated Dockerfiles now includes `ubuntu:24.04` and `alpine:3.21` runtime stages (closes #132).
- `springdocker verify` Trivy scans the Dockerfile path and its containing directory by default; use `--trivy-scan-project-root` to scan the full project root (closes #134).
- Recipe example Dockerfiles wired to `.springdocker.toml` config (closes #128).

### Deprecated

- Benchmark legacy script delegation (`--use-legacy-scripts`, `SPRINGDOCKER_LEGACY_SCRIPTS`, and `[benchmark].legacy_scripts` in `.springdocker.toml`) is deprecated and will be removed in **v2.0.0**. The internal benchmark runner is the default since 1.0.x; legacy mode now emits a warning when used (closes #137).

### CI

- The `supply-chain` job Trivy filesystem scan now **fails CI** on unfixed **CRITICAL** vulnerabilities (`exit-code: 1`). HIGH and below remain informational only in that job; use `springdocker verify` locally or in your pipeline when you want HIGH+CRITICAL gates on Dockerfile build context (closes #139).

### Internal

- `configure_wizard.py` test coverage brought to 100% (closes #138).
- Mypy Phase 2 strict modules: `services.project_service`, `services.dockerfile_service`, `services.benchmark_service`, and `regression` (closes #136).

## [1.1.0](https://github.com/mnafshin/springdocker/compare/v1.0.4...v1.1.0) (2026-06-20)

### Breaking changes

- Remove legacy Dockerfile generation delegation (`--use-legacy-scripts`, `wizard_args`, and `[dockerfile].legacy_scripts` on `dockerfile generate`). Use `springdocker configure` for interactive setup and `springdocker dockerfile generate` for CI. The sample `tools/dockerfile_wizard.py` script is retired (prints migration guidance).

### Features

- `springdocker explain --config-aware` connects Dockerfile output to resolved `.springdocker.toml` options, option sources (`default` / `project`), and drift detection vs `dockerfile generate`.
- `springdocker verify --check-config-drift` validates config SSOT compliance (drift, embedded SBOM, non-root USER, configured JVM flags).

### Internal

- Ruff lint rules expanded to bugbear (`B`), pyupgrade (`UP`), and simplify (`SIM`) with baseline cleanup; gated in CI (closes #84).
- Mypy gradual strictness: Phase 1 module overrides, latent type fixes, typing roadmap (closes #90).
