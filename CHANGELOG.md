# Changelog

Releases are generated by release-please and published from tagged builds.

## Unreleased

### Breaking changes

- Remove legacy Dockerfile generation delegation (`--use-legacy-scripts`, `wizard_args`, and `[dockerfile].legacy_scripts` on `dockerfile generate`). Use `springdocker configure` for interactive setup and `springdocker dockerfile generate` for CI. The sample `tools/dockerfile_wizard.py` script is retired (prints migration guidance).

### Features

- `springdocker explain --config-aware` connects Dockerfile output to resolved `.springdocker.toml` options, option sources (`default` / `project`), and drift detection vs `dockerfile generate`.
- `springdocker verify --check-config-drift` validates config SSOT compliance (drift, embedded SBOM, non-root USER, configured JVM flags).

### Documentation

- [docs/team-adoption.md](docs/team-adoption.md) — team rollout guide (mental model, CI pipeline, profiles, FAQ, legacy migration).

## 1.0.3

- Fix import-time dependency behavior so non-benchmark commands (`init`, `doctor`, `inspect`, `dockerfile generate`) no longer fail when `requests` is not installed.

## 1.0.2

- Refactor Dockerfile generation internals into grouped build/runtime/supply-chain configuration models while preserving compatibility.
- Strengthen benchmark subsystem reliability with explicit command timeouts, container cleanup, and optional benchmark dependencies.
- Expand plugin architecture to six extension points with reference plugin examples.
- Add Spring AOT and native AOT Dockerfile recipe support.
- Improve docs organization by consolidating benchmark comparison content into benchmark methodology.
